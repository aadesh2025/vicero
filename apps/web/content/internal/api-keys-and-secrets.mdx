## The one that will hurt you

**`SECRET_KEY` is not only a signing key.** `app/core/crypto.py` derives the Fernet
encryption key from `sha256(SECRET_KEY)`, and that key encrypts:

- every tenant's provider API keys (`provider_credentials.api_key_enc`), and
- every channel's tokens and secrets.

Rotating `SECRET_KEY` therefore does not merely invalidate sessions. It makes every stored
credential in the system undecryptable, for every tenant at once, with no error until
something tries to use one. Treat rotation as a migration with a re-encryption step, not as
a config change.

Pointing an agent at a provider with no key configured does not degrade to a slower model.
Every turn fails with `llm.provider_unavailable`. Check before switching a client's agent.
</Callout>

## The `.env` formatting trap (ADR-044)

A comment must never share a line with an **empty** value:

```bash
GEMINI_API_KEY=            # get one at ai.google.dev   ← WRONG
```

The spaces after `=` are consumed as the separator, so `#` starts the value and the comment
text *becomes the key*. This shipped a placeholder to Google as a real API key once.

`KEY=value  # note` is fine. `config.py` defensively drops comment-only values and
`_warn_malformed_keys()` catches a value containing a space, tab or `#` — but **Compose's
`env_file` parser does neither**, so the trap is still live for anything Compose reads.

## Startup warnings

`_warn_missing_secrets()` in `app/main.py` logs loudly for a missing `GROQ_API_KEY` or
`N8N_API_KEY`, an insecure `SECRET_KEY` in prod, and malformed keys. `LLM_FORCE_FAKE` gets
an unmissable warning — and an `error` in prod — because a fake-forced process answers
every chat with `echo: <message>`, which reads exactly like a broken model rather than a
config choice. An hour was lost to that once.
