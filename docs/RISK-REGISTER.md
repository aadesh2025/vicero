# RISK-REGISTER.md — BotForge known risks (pre real-client / pre-audit)

> Compiled 2026-08-24 from the project's own session log (`CLAUDE.md` §11) and the
> `docs/11`/`docs/13`/`docs/14`/`docs/17` tracks. Every item here is something the
> project has already documented about itself — this is not new discovery, it's a
> single prioritized view of gaps that are currently scattered across ADRs and
> progress notes. Re-derive this list from the source docs periodically; it will
> go stale the moment a gap is closed or a new one is found.
>
> Scoring: **Severity** = how bad if it bites. **Likelihood** = how likely it bites
> given current usage (near-zero real traffic today). Both `Critical/High/Medium/Low`.
> Sorted by Severity × Likelihood-adjusted priority, worst first.

| R15 | Security / integrations | **n8n webhooks accepted unsigned calls.** BotForge signs every call it makes to an n8n webhook, but no shipped workflow verified the signature, so anyone who learned a webhook URL could call the automation directly — bypassing the agent, RBAC, budget limits and every input check. **Closed in the repo:** (2026-09-24) the four demo workflows, the provisioning template and both example workflows verify HMAC-SHA256 over the raw body (constant-time, 300 s replay window, fails closed); `scripts/provision-client.mjs` refuses to clone a template without the verify node; `tests/test_n8n_workflows_signed.py` pins every JSON in `infra/n8n/`. (2026-09-25, ADR-089) **bind-time enforcement** — `POST /v1/tools/n8n/bind` inspects the workflow (by id, or resolved from a pasted URL through the n8n API) and refuses one that would accept an unsigned call; `GET /v1/admin/n8n-signature-audit` sweeps every already-bound tool across all orgs; the **signing secret now has one home** (root `.env`; `infra/.env` copy removed, `make up` passes both env files). **Still open:** (b) there is no production n8n yet (`docker-compose.prod.yml` has none) and it must be given `N8N_WEBHOOK_SIGNING_SECRET`, `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` and `NODE_FUNCTION_ALLOW_BUILTIN=crypto`. Known limits of what is closed: the bind check is a structural lint (someone determined can fake the marker strings; the real verifier is proven only for the shipped JSONs), it only runs at bind time (a workflow edited in n8n *after* binding is caught only by re-running the audit), and the audit has not yet been run against a real production n8n. | High | Low today (no production n8n, nothing reachable); High once n8n is exposed | Found 2026-09-24 testing demo agents: an unsigned `curl` to a workflow URL ran the automation. Verified after the fix with an 8-case attack matrix per workflow (no headers, wrong MAC, no timestamp, 10-min replay, future timestamp, tampered body, wrong secret, empty secret — all 401) and a real agent turn (signed by BotForge, accepted). Bind gate and audit: `tests/test_n8n_signature_gate.py` (all 7 shipped JSONs pass; a bypassed/decoy/rawBody-off/unconsulted verifier is rejected; unsigned bind by id and by URL refused; signed accepted; audit flags a pre-existing unverified bind). | **Close when** the production n8n exists and is configured as in docs/07 and infra/n8n/README.md, and `GET /v1/admin/n8n-signature-audit` against it reports 0 unverified / 0 unresolved. |

## How to use this

- **Before onboarding client #1 with real data:** clear R3 and R15 at minimum (and run the R2 pre-launch check) (**R1
  closed 2026-09-23**, ADR-082; **R4 measured 2026-09-23**, see docs/15 §11; **R14 fixed
  2026-09-24**, ADR-083). R2 is a same-day
  check against the new database (a document, not code — and not an incident). R3 is the one
  that needs a human decision (budget/vendor for an external review) — flag it to whoever owns
  that budget rather than trying to self-serve it with more self-authored red-team fixtures,
  which is the exact blind spot R3 describes.
- **Before promising any uptime/response-time SLA:** size the DB connection pool and Celery
  worker concurrency deliberately using the R4 numbers (docs/15 §11.1) — the defaults measured
  there are not production-sized.
- **Re-derive, don't just re-read, this file** once real usage starts — a risk register
  written before any real traffic is a prediction, not a measurement. The first real
  incident should prompt a rewrite, not just a new row.
